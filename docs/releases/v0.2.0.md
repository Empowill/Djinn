# Djinn v0.2.0

v0.2.0 brings the full Djinn QoL cycle to the window and the command line: the Djinn's eye follows every driven batch across the screen and speaks from the Lamp pill, the driven lead runs on Antigravity as well as Claude Code and Codex, and the Summoning Circle picks the provider and model for every worker role across all projects. Workers can now run as interactive **ifrits** that keep dev servers lit, bounded **investigations**, or multi-round **mockups**, and deliver **tilasms** you can annotate inline to iterate or launch follow-up work in one batch. Questions launch planned tasks directly on a plain answer, fold earlier versions on the card, and can be set aside for **Later** or put to **Sleep** until tasks finish, a pull request merges, or a date passes. Azimas run in rank order and merge in batches, the Hourglass adds a full **Disk** breakdown alongside side-by-side wish heatmaps, Auto load mode follows only load outside Djinn and rides out network drops, and the Grimoire lives inside the side panel.

Djinn is a local desktop application that turns what you wish into work done by coding agents (Claude Code, Codex, Antigravity) on your own machine, with your own accounts. One *Djinn*, the lead agent, splits each wish into tasks; *workers* do them in their own Git worktrees; Djinn schedules, checks and merges their work, and asks you only what only you can decide. New to Djinn? [v0.1.0's notes](https://github.com/Empowill/Djinn/releases/tag/v0.1.0), [v0.1.1's notes](https://github.com/Empowill/Djinn/releases/tag/v0.1.1), and [v0.1.2's notes](https://github.com/Empowill/Djinn/releases/tag/v0.1.2) describe all it does.

## Install

Install Djinn with a single command, no administrator rights or `sudo` needed:

**macOS and Linux:**
```sh
curl -fsSL https://github.com/Empowill/Djinn/releases/latest/download/install.sh | sh
```

**Windows (PowerShell):**
```powershell
irm https://github.com/Empowill/Djinn/releases/latest/download/install.ps1 | iex
```

The script picks the archive for your system, checks it against `SHA256SUMS`, and puts `djinn` in your own folders. On Linux without WebKitGTK it installs a build that opens Djinn in your browser. Then run `djinn up`. Djinn asks for no API key: the work is done by the agents you installed and signed in to.

macOS builds are not signed yet. `install.sh` (through `curl`) is not affected; `Djinn.app` downloaded with a browser must be allowed once in *System Settings › Privacy & Security*, or with `xattr -dr com.apple.quarantine Djinn.app`.

## Djinn's eye, driven lead across all three agents, and the Summoning Circle

When Djinn drives the lead (the default when `"leadDriven"` is unset or `true` in `settings.json`), **Talk to the Djinn** leaves the header: a seat chip at the top of the flying carpet and each wish switches the Djinn across Claude Code, Codex, or Antigravity (`djinn lead move`, `djinn lead add-account`), the collapsible right-side **Lead** journal offers **Retry** on the latest batch (`djinn lead journal`, `djinn lead sessions`, `djinn lead show`), and each wish's **History** tab interleaves lead batches with the commands they ran. Beside **Write to the Djinn**, **the Djinn's eye**—drawn from the seal in an emerald socket—wakes when a batch starts, flies across the page as the Djinn reads, takes the colour of the batch's events, rests on what you focus, and holds the Djinn's replies in a bubble on the Lamp pill.

**The Summoning Circle** in the side panel (`djinn lead get-circle`, `djinn lead set-circle`) chooses one signed-in provider and verified model for each role across all projects: Djinn the lead, investigation, mockup, ifrit, work, merge correction, merge review, and question investigator, each defaulting to **Same as lead**. Changing a role's model offers to switch open tasks in place (`djinn task update-models`), and the **Models** menu in a wish's header switches the open tasks of that wish alone. Djinn's own merge corrections and merge reviews run on the project's configured provider and model instead of assuming Claude Code.

Session usage and cost are summed across resumes and forks rather than replaced by the last turn, include Claude thinking tokens, 1-hour cache reads, and current model rates, back off automatically on per-minute rate limits, and hold only the proven exhausted model when a quota limit is reached.

**Still needs:**
- Day-to-day use of the driven lead so far is with Claude Code on Linux; Codex and Antigravity driven leads are covered by tests against recorded streams and not tried on a live run yet.

## Tilasms with inline comments, investigations, mockups, and ifrits

**Tilasms** (`djinn tilasm create`, `djinn tilasm list`, `djinn tilasm get`) open full size over the question they explain or from a wish's **Tilasms** tab. Select any passage or click an element in a tilasm to attach an inline comment—or write general comments in the side column—then send every draft comment in one batch with **Iterate** (to revise the exploration) or **Launch** (to start the work), while tracking the Djinn's replies and comment status across versions (`djinn tilasm comments`).

Two new exploration kinds feed tilasms without touching your branch: **investigations** (`--kind investigation`, bounded in time and cost to study a codebase or failure) and **mockups** (`--kind mockup`, multi-round visual prototypes). Both preempt regular work, keep their files in their own worktree without merging into the wish branch, and conclude with a tilasm and a decision question.

**Ifrits** (`--kind ifrit`, on Claude Code or Antigravity) are interactive workers for pair sessions and live previews: an ifrit stays lit in vermilion while you are active in the window or its terminal, runs long-lived dev servers through `djinn serve` with clickable local port links on its card, holds command gates without the one-hour worker timeout, warns after 30 minutes of inactivity before going out to free its slot and ports, relights on demand (**Relight** or `djinn task send`), and integrates through the project's commit checks when you close it.

**Still needs:**
- Ifrits run on Claude Code and Antigravity and are not supported on Codex yet; inline tilasm comments, investigations, mockups, and ifrits are not checked by hand on macOS and Windows yet.

## Questions that launch planned work, fold their versions, and wait on your schedule

When a question option carries a planned task (`Builds:`, `Iterates:`, `Investigates:` in `djinn question ask` or `djinn question revise`), the card names the task it will start and its primary button becomes **Build**, **Iterate**, or **Investigate**: answering without a note starts that task immediately without waiting for a lead turn, while adding a note sends your adjustment to the Djinn first.

Question cards now show a single current context, with **Versions (N)** folded in the top corner so you can read Tour 0 and each revision round on demand. The attention bar at the top of the window lists only red and orange questions that hold up a wish, grouped by kind so long queues never overflow the bar.

Every question can be deferred on your schedule: **Later** (`djinn question later`) moves a question to the bottom of its wish's list with a timestamp, and **Sleep** (`djinn question sleep --until …`) sets a question aside until specific tasks complete, a pull or merge request merges, or a date or duration passes, then wakes it for the Djinn to check before asking you again. Workers can also ask a blocking question (`djinn question ask --wait`), release their slot while keeping their worktree and session, and resume automatically with your answer.

## Azimas in rank order, batch merges, project health, and the diff drawer

**Azimas** now have an explicit rank inside each wish (drag cards to reorder, or run `djinn task rank`): both the worker scheduler and command gates serve higher-ranked azimas first. Azima cards show **Watching** when only a pull request watcher remains active, and **Merged into main** as soon as their branch or pull request lands in `main`.

Finished tasks integrate in batches so commit checks run once for the batch, while push checks run in their own worktree on a frozen commit without holding up subsequent merges; merges and pushes take command gates ahead of workers and keep one worker slot free on multi-slot machines. `djinn task spawn` warns when a new task's scope overlaps open tasks, and each worker receives its own `$DJINN_SCRATCH` directory that is cleaned up with its worktree.

The project configuration drawer opens on **To fix** when action is required, watches the project's reference branch (`djinn project set-branch`, `djinn project acknowledge`) for `.agents` and skill updates, manages **Inbox** sources (`djinn inbox plug`, `djinn inbox unplug`) with three-sentence summaries, and marks projects needing attention with a flaming red gear. On any task card, **See the diff** and **See uncommitted files** (`djinn task diff --uncommitted`) open in a right-hand drawer with a collapsible folder tree.

## The Hourglass with disk breakdown, the Grimoire, and calm Auto mode

**The Hourglass** now has three tabs: **Resources** places machine CPU and memory graphs side by side with worker heatmaps grouped by wish, **Gates** breaks down command gate wait and run time by project, and **Disk** shows a whole-disk bar followed by **Djinn and its workers** (worktrees, scratch folders, and data by project) and **Machine** caches and Docker storage grouped into **Safe**, **Rebuilds**, and **Data loss** with copyable cleanup commands.

**Auto** operating load mode now measures only load outside Djinn (subtracting Djinn's own cgroup CPU usage on Linux) with a 2-minute step-down and 10-minute step-up hysteresis, never drops notches when you move the mouse, explains its current notch on hover, and rides out network outages by probing connectivity, pausing external work, and rerunning network-failed checks once the connection returns.

**The Grimoire** (the built-in documentation) now opens inside the side panel right under the Hourglass, sharing Djinn's waking splash screen, mineral palette, custom concept icons, and the four-step text-size preference (**Large**, **Default**, **Compact**, **Very compact**).

**Still needs:**
- Disk storage breakdown and Linux cgroup subtraction in Auto mode are verified in live use on Linux and by unit tests; not checked by hand on macOS and Windows yet.

## Under the hood

- State files (`settings.json`, `run/` process records, stream logs, and lead files) are written atomically through temporary-file sync and rename, and stopping Djinn lets any in-flight Git step finish cleanly before exit.
- Background daemons and helper processes spawned inside a task or gate command are tagged with `DJINN_MARK` and reaped with their process group, Linux systemd transient scope, or Windows job object when the command or task finishes.
- Worker worktrees share `golangci-lint` and Go build caches, and heavy Go test packages run in parallel.

## Fixed

- Dead keys and accented characters (such as circumflex and grave accents) in the embedded terminal on Linux WebKitGTK no longer drop or duplicate characters.
- Task lists, journals, and tilasms keep their scroll position anchored on what you are reading when new items arrive or existing cards revise.
- Resumed and forked agent sessions accumulate their full token and cost history instead of resetting to the last turn, and per-minute rate limits wait and retry without marking the seat's quota exhausted.
- Answering a question that launches a planned task or revising a question under investigation updates the card and wish state at once without duplicate notifications to the lead.

## Upgrading from v0.1.2

Nothing to do: your data folder, wishes, azimas, tilasms, and lead batch journal are kept as they are. Driven lead remains the default (now available on Antigravity as well as Claude Code and Codex), and your existing provider and model settings populate the **Summoning Circle** automatically. To use the interactive lead terminal instead of the driven lead, set `"leadDriven": false` in `settings.json` in Djinn's data folder.

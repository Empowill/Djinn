# Djinn v0.1.1

v0.1.0 was published without binaries; v0.1.1 is the first installable release.

Djinn is a local desktop application and orchestrator that turns your high-level intents into reality through autonomous coding agents. It provides a native window, a local server, and a command line to guide, supervise, and collaborate with your agents while keeping you in complete control.

## Install

Install Djinn with a single command—no administrator privileges or `sudo` required:

**macOS and Linux:**
```sh
curl -fsSL https://github.com/Empowill/Djinn/releases/latest/download/install.sh | sh
```

**Windows (PowerShell):**
```powershell
irm https://github.com/Empowill/Djinn/releases/latest/download/install.ps1 | iex
```

## Djinn is a native window, the same interface as in the browser, where you talk to the lead, by voice too

Djinn runs as a native desktop application built with Wails v3, embedding its React interface without Node or Electron at runtime. It adapts to your system's light and dark appearance and communicates with the Go backend over low-latency Connect streaming. If WebKitGTK is not installed on Linux, or when passed `--browser`, Djinn seamlessly serves the exact same interface in your web browser behind a secure local token.

**Still needs:**
- Not checked yet on macOS to compare rendering with Linux by hand (`djinn up`).
- Not checked yet on WKWebView (macOS) and WebView2 (Windows) for stream latency benchmarks (`check-window`).
- Voice input to the lead is planned for a future update.

## What waits for you comes first, every question reads clearly, and tilasms keep what explains a wish: you understand and decide at a glance

Djinn prioritizes what needs your attention. The Decision Log and status bar surface pending questions, while workers keep running in the background. Multiple-choice questions offer clear recommendations you can approve immediately with **Rub the lamp**, or investigate beforehand with **Enlighten me**. Tilasms provide rich, versioned, and searchable visual artifacts—Mermaid diagrams, interactive HTML, and data models—sandboxed safely inside the window and addressable via `djinn://tilasm/<id>`.

**Still needs:**
- Not checked yet on physical macOS and Windows for external `djinn://tilasm/<id>` link activation by hand (verified on Linux).

## Every request finds its wish: routed to the right one, started from a wish template, or taken in from outside as a proposed wish

Incoming requests are intelligently routed (`djinn wish route`) without calling a paid model. Djinn analyzes project remotes, issue/PR numbers, title keywords, and recent context to recommend filing the request into an existing wish, starting a new wish, or queueing it if three active wishes are already running. Interactive routing cards let you confirm with a click, and pre-built templates (such as `babysit-pr` and `babysit-mr`) automate common multi-step developer workflows.

**Still needs:**
- Not checked yet on a live model autonomously routing requests from brief instructions without human guidance.
- Not checked yet on live GitLab merge requests for end-to-end `babysit-mr` shepherding to merge.

## Djinn decides, starts, resumes, integrates and pushes the workers' work by itself, in Go

The core orchestrator is written in pure Go. It schedules tasks according to their dependency graph, manages concurrent worker execution, and persists all state durable to disk so work resumes seamlessly after interruptions or restarts. Before integrating completed tasks into your Git repository, Djinn enforces quality gates (`djinn gate run lint`, `test`) to ensure clean history and passing tests before any branch is pushed.

**Still needs:**
- Not checked yet on a lead spawning phase 3 tasks autonomously on a live project.
- Not checked yet on local Ollama/Gemma model dispatch benchmarks versus pure Go dispatch rules.

## Workers start fast, with the right context and the right model, as many as the machine holds

Workers operate in isolated Git worktrees (`projects/*/worktrees/*`) with minimal overhead. The window streams terminal output in real time and tracks token expenditures per worker and wish. Djinn monitors system CPU and memory capacity to prevent overwhelming the host machine, and allows pausing, resuming, or stopping workers at any moment.

**Still needs:**
- Not checked yet on a real benchmark measuring idle standby cost of warm workers with paid models.
- Not checked yet on Linux systems with systemd CPU controller delegation enabled for per-worker cgroup capping.

## Djinn can hand a task to Google's Antigravity CLI (agy), next to Claude Code and Codex, within what Google's terms allow

Djinn integrates Google's Antigravity CLI (`agy`) as a first-class worker provider alongside Claude Code and OpenAI Codex. The adapter auto-detects local credentials via Application Default Credentials (ADC), streams turn-by-turn execution into the Djinn interface, and respects sandbox and plan mode parameters.

**Still needs:**
- Not checked yet on a real paid run signed in with live Google ADC accounts.
- Not checked yet on live headless runs to confirm exact plan mode and sandbox enforcement.

## One wish spans several projects, and a project's skills serve in another

A single wish can coordinate work across multiple Git repositories, allowing full-stack or multi-repo tasks to progress in harmony. Skills defined in one project (`.agents/skills/`) can be summoned into another, equipping agents with specialized instructions and tools. Wishes can be exported into single portable bundles (`djinn wish export`) and restored on other machines (`djinn wish import`).

**Still needs:**
- Not checked yet on a real paid agent run executing a summoned cross-project skill.

## Everything starts from the protos: minimal data, a command line generated and documented, everything in English, clean code

Djinn's architecture is defined by Protocol Buffers. The comprehensive command-line interface (`djinn`) is generated directly from protobuf service definitions with built-in validation, shell completion, and inline help. Djinn integrates deeply with your desktop via the global summon shortcut `Ctrl+Alt+Space`, native desktop notifications, and an embedded Model Context Protocol (MCP) server for external agent access. All state is stored locally in an embedded SQLite database with write-ahead logging (WAL) and full sync durability.

**Still needs:**
- Not checked yet on physical GNOME, macOS, and Windows desktops for global shortcut keypress and notification clicks by hand.
- DuckDB analytics for long-term usage metrics are planned after v1.

## Djinn runs on Windows as well as on macOS and Linux

Windows is treated as a first-class target. On Windows, Djinn utilizes WebView2 for rendering, communicates over loopback HTTP with authentication tokens, and manages background worker processes via Windows Job Objects to ensure complete cleanup without orphaned processes. Windows amd64 and arm64 binaries are built without CGO and include embedded icon resources.

**Still needs:**
- Not checked yet on physical Windows 11 hardware for native window opening and live stream verification.
- Continuous integration Windows job currently runs non-blocking while dependencies stabilize.
- Worker execution in worktrees and CPU/memory limits on physical Windows machines.

## Your wishes follow you: backed up on your server, shared online, and later spread over your other machines

Closing Djinn loses nothing: every write is a durable SQLite transaction. Full machine backups (`djinn backup`) create consistent snapshots (`VACUUM INTO`) while Djinn runs, and can be restored cleanly (`djinn backup restore`) without overwriting active data. In addition, `djinn wish sync` generates standalone, responsive HTML status summaries in real time for sharing and hand-offs, without sending credentials or secrets off-machine.

**Still needs:**
- Not checked yet on a real multi-user hand-off of a published wish status link.
- Distributed task execution across trusted machines is planned after v1.

## Djinn installs in a few minutes, and updates from inside the app

Getting started takes a single terminal command without administrative privileges or system dependencies. When a new release is available, Djinn detects it via GitHub Releases and offers an in-app update banner. One click or a `djinn update` command replaces the binary in place and restarts smoothly.

**Still needs:**
- Not checked yet on a fresh account on macOS and Windows without administrator rights.

## Every release ships ready-made binaries for each target, built by CI, so that nobody needs a compiler, CGO or a system package

Every release produces pre-compiled archives for Linux (amd64 and arm64, GTK 3 and GTK 4), macOS (universal binary `Djinn.app` in `.zip`), and Windows (amd64 and arm64 executables in `.zip`). Each archive includes cryptographic verification (`SHA256SUMS`), `NOTICE`, and `docs/THIRD_PARTY_NOTICES.md`. `go install` without CGO remains supported as a universal fallback.

**Still needs:**
- Not checked yet on physical macOS hardware (opening unsigned `Djinn.app` from Finder, Dock/Launchpad icon display, and Gatekeeper quarantine allowance). macOS builds are currently unsigned; browser downloads may require running `xattr -dr com.apple.quarantine Djinn.app` or allowing the app in *System Settings > Privacy & Security*.
- Not checked yet on physical Windows hardware for execution without SmartScreen warnings.
- Arm64 Linux GTK 3 and GTK 4 binaries are built by CI but not verified on physical hardware.

## Under the hood

Internal tasks focus on speed, durability, and testing integrity:

- **Tested end to end (T05)**: The entire automated test suite—spanning Go unit tests, UI component tests, and 31 Playwright end-to-end specifications—runs in under 2 minutes. Slow tests exceeding 2 seconds fail CI immediately. All agent interactions are validated using deterministic mock providers and recorded event streams; tests never call paid models. In addition, real native window testing is automated via an internal MCP server (`go tool task e2e-native`).
- **Engineering foundation**: SQLite operates in WAL mode with `synchronous(FULL)` without CGO (`modernc.org/sqlite`), using a reflection-based ORM over Protocol Buffers. Strict quality gates (`djinn gate`) guard code quality, linting, and formatting before any commit or push.

**Still needs:**
- Native window end-to-end test suite (`e2e-native`) not checked yet on macOS.

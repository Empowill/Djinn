## Couverture pertinente

Les tests natifs utilisent le vrai pipeline de passages avec des fixtures de processus Claude et Codex : permissions de qualification, définition complète de timeline, filtres lead/worker, première étape adaptée, événements tardifs, questions bloquantes et indications humaines. Les tests du vrai hook du renderer vérifient aussi la reprise après annulation et l’effacement d’une proposition périmée. Les anciennes missions fixes et `discussion_type` restent couvertes.

Les tests de scan vérifient les limites de lecture, l’exclusion des secrets/liens symboliques, les emplacements observés, les preuves immuables, le modèle configuré et les permissions des deux harnesses, le JSON de contexte borné et le passage explicite en repli local. L’annulation d’un provider ignorant SIGTERM est testée jusqu’à SIGKILL sous les deux fixtures.

Les tests de configuration utilisent le vrai composant avec un harness de hooks : annulation à la fermeture ou au changement de dossier, résultat tardif ignoré, application idempotente, préférences et anciennes données de workflow préservées, erreurs de sauvegarde visibles.

La restitution est testée avec actions et supports dans leurs groupes réels, ordre des tours, anciennes révisions et groupe sans identifiant. Un test de rerender React avec DOM minimal reproduit l’arrivée d’un nouveau tour et l’événement tardif `toggle(false)` de l’ancien accordéon ; le nouveau reste ouvert.

Le formulaire de nouvelle mission est testé avec un projet possédant une ancienne politique imposée : celle-ci ne choisit plus le parcours de la nouvelle mission. Les préférences et indications sont transmises, puis la qualification prépare une nouvelle timeline. Les scénarios Playwright et le smoke Electron ont été adaptés ; leur collecte seule ne vaut pas exécution visuelle.

Les régressions de reprise Codex 0.1.9 (`excludeTurns: true`, conservation de la cause d’interruption et reconnexion après fermeture du serveur) restent incluses dans la suite. Les vrais échecs ne sont pas masqués.

## Limites de vérification

Aucun modèle réel n’a été appelé pendant les tests ou l’essai de scan Dolmen. Les fixtures vérifient les règles communes aux harnesses, pas l’identité des réponses de modèles réels.

Les trois tests HTTP ignorés nécessitent des sockets loopback indisponibles dans cette sandbox. La tentative de lecture de `http://127.0.0.1:4317` a échoué, code curl 7 ; aucune URL prête n’est annoncée et aucun serveur n’a été lancé.

Les tentatives précédentes de Chromium et de contrôle UI étaient bloquées ou avaient expiré. Aucun screenshot ni parcours graphique 0.2.0 n’est revendiqué. Les contrôles de rendu et d’interaction React ne remplacent pas la review visuelle Electron. L’ouverture du bundle et les essais avec Claude/Codex réels restent humains.

Pour l’aperçu, le script est `dev` dans le paquet racine `.` ; Djinn peut en gérer le processus et vérifier la réponse avant d’annoncer une URL.

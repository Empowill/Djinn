# Djinn 0.1.6 — sélection des modèles

Les champs libres de création et de configuration de mission sont remplacés par un sélecteur de modèles recherchable, adapté de T3 Code. La sélection affiche un nom lisible et transmet l’identifiant exact au fournisseur. Le choix « Défaut du fournisseur » conserve la configuration de la CLI.

Codex fournit son catalogue via `model/list`, dans un transport dédié aux métadonnées, sans créer de thread ni lancer de génération. Pagination, modèles masqués, erreurs, mise en cache et fermeture du processus sont pris en charge. Claude Code reprend le manifeste de T3, filtré selon la version de la CLI installée. Ce manifeste décrit la compatibilité des versions ; les droits du compte restent contrôlés par Claude Code lors de l’exécution.

Un choix existant absent du catalogue reste visible. Il n’est pas remplacé automatiquement. Changer explicitement de fournisseur remet le champ sur le défaut du nouveau fournisseur. Recherche, flèches, Entrée, Escape, clic extérieur et nouvelle tentative sont disponibles. Le premier Escape ferme le sélecteur ; le suivant ferme la modale.

Référence : T3 Code, commit `3e6b45028ceec5820dacb37dc3852470ebdc9411`, composants `ProviderModelPicker`, `ModelPickerContent`, `modelPickerSearch`, catalogue Claude `model-manifest.json`. Attribution MIT incluse dans `THIRD_PARTY_NOTICES.md` et le bundle.

Travail de portée moyenne : UI déléguée au worker Codex `gpt-5.6-luna`, effort `max`; découverte native, contrats, intégration, vérification et livraison supervisés par l’agent principal. Vérification node déléguée au `verification-runner`. Aucun commit ni push.

Fichiers : `src/model-picker.tsx`, `src/app.tsx`, `src/styles.css`, `src/types.ts`, `electron/provider-models.cjs`, `electron/claude-models.json`, `electron/main.cjs`, `electron/preload.cjs`, tests de catalogue, fixture Codex, vérification Electron, test de workflow, version et notices.

La livraison comprend aussi le retour au premier design de timeline : cercles et traits, appliqués aux étapes configurables. Les bandeaux de contexte et d’activité ont été retirés à la demande de l’utilisateur. Les cartes d’agents et la timeline conservent les états ; l’accès au chef est une action compacte dans la barre des vues. Le minuteur global, devenu inutile après suppression du bandeau d’activité, est retiré.

Les échecs intermédiaires provenaient de sélecteurs de tests : les options des autres champs entraient dans le comptage, le nom accessible du fournisseur était plus long que prévu, et un test de création cliquait la mission existante homonyme. Après contrôle visuel, le bouton de configuration du workflow est passé sur la ligne de timeline et la lisibilité des étapes futures a été rétablie.

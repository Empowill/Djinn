# Djinn 0.1.9 — reprise des longues conversations Codex

Une reprise de la mission « Workflows flexibles et orchestration fiable »
retéléchargeait tous les tours du thread natif. La réponse dépassait la limite
de transport de 1 000 000 caractères. Djinn arrêtait alors le serveur, dont la
fermeture propre avec le code 0 masquait la cause initiale.

La demande `thread/resume` utilise désormais `excludeTurns: true`. Codex garde
l'historique et reprend le même thread, sans le renvoyer dans cette réponse.
La limite mémoire reste identique. Une interruption du transport conserve son
erreur initiale, même si le processus se ferme avec le code 0.

La reproduction avec le vrai binaire Codex et le thread concerné échouait sur
une réponse de 1 103 485 octets. La reprise du même thread sans les tours a
réussi, avec 10 109 octets et aucun nouveau tour de génération.

Les régressions couvrent un historique de 1 200 000 caractères, la préservation
de la cause d'arrêt, et la reprise sur une nouvelle connexion après une
fermeture du serveur. La version inclut les changements de Djinn 0.1.8.

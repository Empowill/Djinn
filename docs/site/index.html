The shape of the project

The lamp and the smoke

A djinn is smoke from a lamp. You look for the lamp; you find the djinn. Djinn is built the same way: a hard lamp, free smoke.

◆ The lamp is hard

What Djinn computes and must never get wrong: wishes, tasks and their states, questions, decisions, gates, the machine, the journal, the limits. Typed in the protos, enforced by code, tested.

No model decides here.

∿ The smoke is free

What the lead shapes for each wish: a section opened on the fly, a diagram, a chart, research notes, a hand-off. Blocks the model writes, shown as written, exported whole.

The model chooses the smoke.

  1. Empty means hidden. No “To decide” without a question.
  2. The model chooses the smoke. A new section is a block, never a code change.
  3. Smoke hardens only when code needs it. Then it becomes a proto field, with tests.

The first rule

Wish for anything, except what no djinn can grant

Like the genie of the lamp, Djinn has its limits. Code enforces them; no option turns them off.

  • I

    It can't kill anybody

    Nothing destructive or irreversible, a deletion, a force push, a deployment, happens without your explicit go.

  • II

    It can't make anybody fall in love

    It never bends anyone else's will: no message, approval or merge sent in your name that you have not seen.

  • III

    It can't bring anyone back from the dead

    What failed stays failed: no made-up result, every claim comes with its evidence.

  • IV

    No wishing for more wishes

    It never grants itself more than it was given: no extra budget, no wider access, no secret it stores or reads.

  • V

    Three wishes at a time

    Never more: three active wishes at most, and as many set aside as you like. It guards your attention, not the machine.

From brief to result

The life of a wish

  1. 1

    You make a wish

    Say what you wish, in a sentence, on one project or several.

  2. 2

    Its lead lays the plan

    Claude Code or Codex splits it into azimas and tasks: a graph without cycle.

  3. 3

    Workers take the tasks

    Each in its own worktree and branch, its events live, its cost measured.

  4. 4

    You decide

    A question comes with its options and a recommendation. Rub the lamp, or ask for light.

  5. 5

    The lead reviews

    Workers never commit: the lead reads each diff, commits in batches, pushes once.

  6. 6

    The wish is granted

    Its page and its export keep it whole: notes, decisions, what each task did.

The words of Djinn

What you will meet

Two words come from the theme: you make a wish, you summon a skill. A few more are borrowed from the old tales, each where nothing plainer would do. Everything else is plain.

Wishes

What you want done. A wish has its projects, one lead, its tasks and its decisions. Three are active at most; the others wait, set aside. Give one priority with djinn wish move; say it is done with djinn wish grant.

The lead

Claude Code or Codex, in a terminal inside the window. It plans the wish, asks the questions, reviews each diff and commits. Djinn brings it back on its session at every start, in its folder.

Azimas ʿazīma

The incantation that binds and commands a djinn. The plan of a wish is a graph of azimas: tasks no worker runs, which work is part of. Only depends_on makes a task wait. djinn plan sync reads them from a project's plan/*.md.

Workers

An agent on one task, in its own worktree and branch. Send it an instruction, pause it, stop it. Stopping Djinn interrupts workers, never loses them: the next start resumes each one in its own session.

Questions, and the lamp's rub

When the lead needs you, it asks: its options, and the one it recommends. Rub the lamp takes the recommendation; Enlighten me sends the lead to dig first. An answered question is a decision: who took it, and the tasks it led to, stay in the Decisions tab.

Gates

Workers share one machine. Tests, builds and code generation take a gate, one at a time: djinn gate run test -- go tool task test. Djinn records what each command cost and, next time, waits for the memory it peaked at.

The machine

Djinn reads what each worker uses, CPU, memory and processes, every five seconds; on Linux from a systemd scope of its own. Another worker starts only when the free memory holds its typical peak. djinn machine show lists them, the busiest first.

Tilasms ṭilasm Coming

The engraved object that holds a power, origin of “talisman”: the material that explains a wish. A folder with an index.html and its sources, kept on your machine, in its own tab, opened by a djinn:// link from anywhere.

Blocks and marks

The smoke: the lead's notes, Markdown and Mermaid diagrams, shown as written. Mark what you read, approve what may go on. One HTML page shares the wish; djinn wish export hands it over in one file.

Nothing is lost

Every write is a transaction with its journal entry, durable through a power cut. A worker stopped by its usage limit waits for the reset, then goes on. djinn backup copies it all, even running.

Every request finds its wish

Something unrelated comes up: open a new wish, file it in another, or keep it here. What comes from outside lands in the inbox; a skill's wish template makes a wish that already knows how to work.

Summoned skills

djinn skill summon app/babysit-mr --into infra lets one project's workers use another's skill, without a copy: they follow the source.

Your attention

Three lamps lit, never more

A djinn grants three wishes. Three are active at most; the others wait, paused, as many as you like. Activate one, and the third active wish steps aside. The flight plan shows the three together.

One command

Speak to the djinn

The window, the command line, MCP and the API are one surface, generated from the protos: a method is a command, a tool of djinn mcp, and an HTTP call. 

# the window, the local server, the lead's terminal
$ djinn up
# a wish, and its plan
$ djinn wish make "Ship the lamp"
$ djinn task spawn <wish-id> --kind azima --title "Polish the brass"
# take the lead's recommendation
$ djinn question answer Q03 yes
# heavy runs, one at a time
$ djinn gate run test -- go tool task test
$ djinn machine show
# the same commands as MCP tools, on stdio
$ djinn mcp

The API

Every public method of Djinn: the commands of djinn, the tools of djinn mcp, and an HTTP API in the Connect protocol, a POST with a JSON body.
